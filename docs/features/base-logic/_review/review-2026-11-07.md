### R3-01 [stage-2] An invalid `BOT_INFO` is trusted without checking. Verdict: **Fix now**

`src/worker.ts:38-40`, `:51-53`. AC: AC-13, AC-15. `parseBotInfo` runs `JSON.parse(raw) as UserFromGetMe` and checks nothing:

- **Not valid JSON:** `buildApp` throws on every update. The app is never cached, so every request logs only
  `webhook_error` and no Bot user gets any reply.
- **Wrong shape:** the most likely case is pasting the full `{"ok":true,"result":{…}}` response from `getMe`.
  `ctx.me.username` is then undefined: the group pointer says "@undefined" (`replies.ts:25`) and a `/cmd@bot` command
  throws inside grammY.

Tests always inject a valid value (`vitest.config.ts:14-24`). Fix: check `id` (number), `username` (string) and
`is_bot === true`. If the value is invalid, log `startup_warning {reason: "BOT_INFO invalid"}` and fall back to `getMe`.
Test both bad shapes.

### R3-02 [stage-2] The main module still exports `buildApp` and `getApp`. Verdict: **Fix now**

`src/worker.ts:43`, `:63`; `test/integration/worker.smoke.test.ts:33-39`. AC: AC-15. workerd registers every exported
function as an entry point, and the pinning test lets any function through. This was the fix record's first follow-up,
and no task tracked it. Fix: move the composition (`buildApp`, `getApp`, the cached app) into its own module. Then
`src/worker.ts` exports only `default`, and the test asserts exactly that.

### R3-03 [stage-2] CI never starts the bundled Worker. Verdict: **Defer**, as spec §8 OQ-5

`.github/workflows/ci.yml` (the last step is `npm run build`, a dry-run bundle only). AC: AC-15. CI would still not
catch the bug fixed in `d631525`, or any other failure that only shows at boot. Deferred because the installed Miniflare
is a beta with a changed constructor API, so a reliable boot check is a task of its own. Until then, `sdd:ship` starts
`wrangler dev` by hand. Owner: Vlad S. Due: before the roadmap's "Bot is live on Cloudflare" step.

### R3-04 [stage-2] The README deploy step leaves out `secret_token`. Verdict: **Fix now**

`README.md:61`. AC: n/a (spec §6.1, SAD §8 Authentication). A webhook registered without the secret header has every
update dropped at `src/worker.ts:68` with a bare 200 and, by design, no log event, so the bot stays silent. Fix: give
the full `setWebhook` curl with `-d "secret_token=<WEBHOOK_SECRET>"`, the same as the local recipe.
