### R-01 [stage-1, medium] T16 two-lookup non-Latin set-city is not reflected in the design docs and has no ADR — **Fix now**

- Where: `src/app/set-home-city.ts:65-71`, `src/domain/city-query.ts:45`; `sad.md:108`, `:133`, `:434`; `spec.md:364`.
- AC: AC-01, AC-16, AC-17, NFR "outbound calls per message ≤ 3".
- Problem: a Cyrillic query makes 2 counted lookups (localized search + English re-fetch). The SAD still says "at most one lookup",
  "language=en" and `lookups (0 or 1)`, and the spec test-plan row says "within one lookup". The decision lives only in `tasks/t16-non-latin-city-names.md`.
- Fix: write feature ADR-0003 (localized search + English re-fetch); update `sad.md` §4/§5/§8 and the spec test-plan edge row to "≤ 2 lookups".

### R-02 [stage-1, medium] No test pins the 1.5 s outbound cutoff — **Fix now**

- Where: `src/adapters/open-meteo/http.ts:4`; `geocoding.test.ts:130-135`, `forecast.test.ts:72-76`.
- AC: AC-04b, AC-10.
- Problem: the hang tests only assert `unavailable` within a 5 s test timeout; any `TIMEOUT_MS` below ~4.9 s passes.
- Fix: spy on `AbortSignal.timeout` and assert it is called with 1500 (or assert elapsed ≈ 1.4–2.0 s).

### R-03 [stage-1, low] "Your city is still X" missing for unknown-country and over-long queries — **Fix now**

- Where: `src/app/set-home-city.ts:38-39`; `src/adapters/telegram/replies.ts:70-72`; `test/integration/city.test.ts:244-256`.
- AC: AC-05, AC-07.
- Problem: the query is parsed before the Home city is loaded, so "Paris, Texas" and a too-long name reply "couldn't find" without
  the current city, unlike "Paris, Japan".
- Fix: load the Home city for `unknown_country` / `too_long` (one D1 read, no lookup) and pass it to the not-found reply.

### R-04 [stage-1, low] Forged webhook gets a 401 with the reason text — **Fix now**

- Where: `src/worker.ts:43` (grammY `secretToken`); `test/integration/telegram-edge.test.ts:51`.
- AC: spec §6.1 (`spec.md:264`, `:267`): forged updates are "dropped silently… a forger learns nothing".
- Problem: grammY answers 401 "secret token is wrong".
- Fix: check the secret header in `worker.ts` before `webhookCallback` and return a bare response with no reason; update the test
  and align SAD flow A wording.

### R-05 [stage-2, medium] One malformed geocoder entry fails the whole set-city as "unavailable" — **Fix now**

- Where: `src/adapters/open-meteo/geocoding.ts:58` (shape check `:13-23`); `geocoding.test.ts:124`.
- AC: AC-04 / AC-04b (quality).
- Problem: any candidate missing `country` / `timezone` / `feature_code` turns the whole answer into `unavailable`; every retry
  fails the same way and spends a counted lookup.
- Fix: skip malformed entries and keep valid ones; `unavailable` only when the body/`results` is malformed or every entry is bad.
  Test one bad entry among good ones.

### R-06 [stage-2, medium] A failed reply overwrites the real outcome with `fault` and triggers a second send — **Fix now**

- Where: `src/adapters/telegram/request-log.ts:38-49`; `src/adapters/telegram/commands/city.ts:11-12`.
- AC: n/a (spec §6 reply rate, §7 KPIs, outbound budget).
- Problem: a 403/429 from `sendMessage` reaches the catch, replaces e.g. `ok` with `fault`, and since `replied` is false sends
  `FAULT_REPLY` too (a Cyrillic set-city then makes 4 outbound calls). No test covers a failing `sendMessage`.
- Fix: record a separate `reply_failed` field without overwriting the handler's outcome; skip the fault reply when the error came
  from the reply itself; add a test where `sendMessage` returns `ok: false`.

### R-07 [stage-2, medium] Webhook secret check fails open when `WEBHOOK_SECRET` is unset — **Fix now**

- Where: `src/worker.ts:43`; `node_modules/grammy/out/convenience/webhook.js:25`.
- AC: n/a (spec §6.1 forged updates).
- Problem: grammY accepts every request when the token is `undefined`; nothing warns if a deploy forgets the secret.
- Fix: fail closed — refuse every webhook and log `startup_error` when the secret is empty; add a test. Implement together with R-04.

### R-08 [stage-2, low] Fault events carry nothing to diagnose them — **Fix now**

- Where: `src/adapters/telegram/request-log.ts:46`.
- AC: n/a (SAD §12 relies on `fault` logs to detect D1 quota exhaustion).
- Problem: bare `catch {}` drops the error.
- Fix: add a secret-free field, e.g. `fault: error.name` (or the grammY method + error code).

### R-09 [stage-1, low] AC-15 secret-in-log checks miss the failure paths the test plan names — **Fix now**
